# 07 SketchThinker-R1 方法的主要局限与潜在弱点

- 日期：2026-10-21
- 论文：《SketchThinker-R1: Towards Efficient Sketch-Style Reasoning in Large Multimodal Models》，[arXiv 2601.02825](https://arxiv.org/abs/2601.02825)
- 问题：What are the primary limitations or potential weaknesses of the methodology presented in this paper?

## 结论

把推理压缩成编号"草图"本身不是问题，主要弱点在于**证据只覆盖了一个很窄的区间，而且关键的新组件没有被单独验证**。论文的核心结论是"推理 token 减少 64%、准确率不下降"：64% 的数字算得没错（64.7%–76.5%），但"准确率不下降"其实只能算"大致持平"，且只在本来就很短的推理和 3B / 7B 的 Qwen2.5-VL 上成立。

## 主要局限（按对结论的影响排序）

### 1. 实验没进入论文要解决的"长推理"区间

- 论文动机是 o1 / R1 那种上千 token 的长推理。
- 但 Vanilla-R1 基线评测时平均只有 182–240 个推理 token（Tab. 1），训练时约 300（Fig. 1d），最大响应长度 2048。
- 实际节省的是每题约 120–185 个 token。论文证明的是"短推理还能更短"，没有检验收益最大、风险也最大的过度思考区间。

### 2. "准确率持平甚至更好"缺乏统计支撑

- **提升很小**：7B 上只有 +0.2 到 +1.9 个百分点；3B 在 MathVision 上比 Vanilla-R1 还低 1.6 个百分点（26.9 → 25.3）。
- **没有误差范围**：全文没有随机种子、方差或置信区间。按我的估算，若 MMMU 用 900 题的 val 集，准确率本身的标准误约 1.6 个百分点。
- **VisuLogic 几乎没有信息量**：四选一，实测随机基线 24.9%，未训练的基座模型为 26.0，论文里所有方法都在 25–28 之间。
- **MathVision 划分不明**：没说用 3,040 题的 test 还是 304 题的 testmini。按图 11 推理耗时与 token 数的比例推测更像 testmini（这是推测，论文未说明）；若如此，0.7 个百分点约等于 2 道题。
- **消融差距在同一噪声范围内**：Tab. 4–7 多数只差 0.2–0.6 个百分点，"二值奖励优于稠密奖励"（62.8 vs 62.6）之类的结论站不住。

### 3. 核心贡献 SketchJudge 没被证明独立起作用

- **风格奖励权重几乎不影响长度**：Tab. 5 没有风格奖励权重为 0 的对照，最低是 0.05。权重 0.05 时已是 65.2 个 token，默认 0.1 时为 64.3。
- **长度主要在 RL 阶段下降**：只做冷启动是 114.5 个 token，再做 RL 降到 64.3（Tab. 3a）。这部分缩短可能来自 RL 本身，而非风格奖励。
- **未训练的提示式评判器效果也差不多**：用它时为 72.1 个 token（Tab. 3d）。
- **没有检验它本身是否可靠**：没有报告 SketchJudge 在留出数据上的分类准确率或鲁棒性。

### 4. SketchJudge 看不到内容，很可能学到的是表面特征

- **训练方式**：GPT-5 改写的编号列表标为 1，原始长推理标为 0。打分时只输入 `[THINKING]`，看不到题目、图像，也不知道答案对不对。
- **后果**：无法判断草图对这道题是否充分，实际上更接近一个"格式 + 长度"检测器。
- **作者承认存在奖励投机**：风格权重高时，"the model focuses solely on achieving a higher sketch-style thinking reward and neglects correctly answering the question"（App. E）。
- **"自适应长度"的说法没有证据**：§2.2 称模型"can still generate relatively long and extensive reasoning for challenging questions"，但没有给出推理长度随难度变化之类的证据。

### 5. 准确率收益与 GPT-5 蒸馏混在一起

- **改写模型影响过大**：用 GPT-5 转换冷启动数据得 62.8，换成 Qwen2.5-72B 只有 59.1（Tab. 3b），比 Vanilla-R1 的 61.0 还低。如果转换只是删字，换模型不该让准确率差 3.7 个百分点；更可能是 GPT-5 补充或纠正了内容。
- **改写提示词只看推理文本**：只有 `{reasoning}`（Tab. 16），GPT-5 在看不到图像和题目的情况下决定哪些是"关键步骤"，视觉细节可能被删掉。
- **数据核查很薄弱**：质量检查只问"关键步骤是否保留"（5 人 × 20 个样本；模型自动检查判定 4.1% 缺关键步骤），没检查原始长推理本身是否正确。
- **可复现性**：方法依赖闭源的 GPT-5。
- **缺少干净的对照**：用 GPT-5 改写但保持原长度和风格的版本。

### 6. 基线比较不对等，效率指标有偏

- **训练预算不同**：SketchThinker 用了 2 万条 SFT + RL + 奖励模型；基线要么只靠提示，要么只做 SFT（C3oT、VeriThinker），要么只做 RL 且没有冷启动（L1、ThinkPrune）。L1 的目标长度没报告，也没有在相同 token 预算下比较。
- **EoT（准确率 / token 数）由 token 数主导**：
  - Constrained CoT 准确率低 2.4 个百分点，EoT 却是 0.749，Vanilla-R1 只有 0.335。
  - Tab. 5 中 0.2:0.4:0.4 准确率掉 2 个百分点，EoT 几乎不变。
- **"token 比所有基线都少"不成立**：7B 的 PhyX 上，Constrained CoT 用 73.4 个 token，少于 75.3；3B 的 MathVision 上，Constrained CoT（63.4）和 Chain-of-Draft（71.5）都少于 72.7，且准确率还低于 Vanilla-R1。这与 Tab. 2 标题"consistently outperforms… in both answer accuracy and reasoning token cost"矛盾。

### 7. 超参数在测试基准上挑选，"泛化"只是近域

- **选择偏差**：所有消融都在 MMMU 上做，而 MMMU 本身就是评测基准；默认奖励权重按 MMMU 的最佳 EoT 选出，所以 MMMU 主结果偏乐观。
- **训练与评测领域一一对应**：

  | RL 训练数据 | 评测基准 |
  |---|---|
  | MMStar | MMMU |
  | MathVista | MathVision |
  | LogicVista | VisuLogic |
  | SeePhys | PhyX |

- **未测试的方向**：OCR、图表、文档、空间推理、视频、开放式生成。
- **模型范围**：只有 Qwen2.5-VL 的 3B 和 7B。

### 8. 可解释性证据薄弱，忠实性没测

- **人工评估规模小**：5 位背景不明的评估者，20 个样本，且只选了两个模型都答对的题；没说明是否盲评，分数（3.95 vs 4.25）没有统计检验。
- **模型评估可能偏向简洁文本**：用 Qwen3-VL-Plus 打分为 4.12 vs 4.33。
- **易读不等于忠实**：短推理可能是事后编出来的，而非真实计算过程（[Turpin et al., NeurIPS 2023](https://arxiv.org/abs/2305.04388)；[Lanham et al., 2023](https://arxiv.org/abs/2307.13702)）。
- **更短可能更难核验**：图 4 的冷启动样例中，"OD = 1/2 AC" 这一步省掉了"D 是 BC 中点"的理由。
- **缺少"不推理直接答"的基线**：如果直接作答也差不多，说明推理本来就没起多大作用，"压缩后不掉点"就是自然的。作为参考，Qwen2.5-VL-7B 官方直接作答分数为 MMMU val 58.6、MathVision 25.07（评测协议不同）。

### 9. 成本核算不完整

- **token 数只算推理部分**：`#Token` 不含图像 token 和提示词的预填充。
- **推理加速比无法推广**：图 11 的推理时间约降为原来的三分之一，但推理服务设置（批处理、推理框架）未说明。
- **训练时间只比了一个阶段**："训练时间 ×0.81"只比较了 RL 阶段（Tab. 15），没算冷启动 SFT、SketchJudge 训练和调用 GPT-5 改写 2 万条数据的成本。

## 作者自己承认的局限

论文没有 Limitations 章节，相关承认散落在四处：

- 风格权重高时会出现奖励投机（App. E）。
- 开源模型改写的数据会降低准确率："at the expense of lower answer accuracy"（Tab. 3）。
- 只做冷启动时"is largely restricted to the training set"（§3.2）。
- 人工评估"is based on a small sample size"（App. G）。

## 与已有文献的矛盾

**测试时扩展 vs "短也行"。** [s1（EMNLP 2025）](https://arxiv.org/abs/2501.19393)表明强制延长思考能提高准确率；过度思考方向的工作（[Chen et al., 2024](https://arxiv.org/abs/2412.21187)）和本文则认为缩短推理不伤性能。

- **判断**：这属于边界条件型矛盾，决定因素是题目难度相对于模型能力，以及基线推理本来有多长。
- **本文无法裁决**：它的证据全落在短基线区间，外加接近随机水平的 VisuLogic。
- **与自身引用的冲突**：论文在相关工作中把 Vision-R1（[Huang et al., 2025](https://arxiv.org/abs/2503.06749)）描述为逐步增加推理长度，而它的冷启动数据正来自 Vision-R1。
- **决定性实验**：按 MathVision 的 5 个难度等级分层，看 SketchThinker 的准确率差距是否随难度扩大。3B MathVision 上的 −1.6 与这个假设一致，但不构成证明。

## 隐含前提与失效推演

| 隐含前提 | 体现在哪里 | 极端情况下如何失效 | 需要什么 |
|---|---|---|---|
| 只看推理文本就能判断哪些是关键步骤 | 改写提示词和 SketchJudge 都看不到图像和题目 | 依赖感知的题目：图表、细粒度计数、多图 | 结合图像和题目来压缩和打分，保留视觉证据步骤 |
| 推理风格可以和内容分开评判 | 风格奖励不看题目、权重固定 | 难的多步题，一律压短会推理不足 | 以难度和答案正确性为条件的简洁奖励 |
| token 数等于计算成本 | `#Token` 只统计推理 token | 高分辨率、多图或视频，图像 token 占大头 | 端到端 FLOPs 和延迟测量 |
| 多选题准确率能反映推理质量 | 四个基准以多选为主 | 像 VisuLogic 这样接近随机水平的场景 | 可核验答案的开放式题目，加上逐步评估 |

可证伪的预测：在 MathVision 难度 4–5 级的题目上，SketchThinker 相对 Vanilla-R1 的准确率差距会随难度单调扩大；若差距不随难度变化，第二条前提成立。

## 报告层面的不一致

这些不改变结论，但影响可复现性：

- **rollout batch size**：§3 写 128，附录 D.3 写 512；文中的 105 个训练步只有按 128 才算得出（每轮 7 步 × 15 轮）。
- **Tab. 8 正文与表格数字不符**：正文说长推理冷启动基线达到 61.8，表中没有 61.8，最高为 62.0。
- **硬件**：§3 写 8 × H200，附录 J 写 8 × H800。
- **表格引用写错**：阶段消融应为 3(a)，数据来源应为 3(c)，训练步数扩展应为 Tab. 10。
- **算法名称**：GRPO 被误称为 "Group Reward Proximal Optimization"。
- **评测细节缺失**：全文没有交代数据划分、解码设置、运行次数和答案匹配方式。

## 建议优先补充的实验

1. 在真正的长推理模型（上千 token）上应用该方法。
2. 风格奖励权重为 0 的消融。
3. "不推理直接答"的基线，并给出准确率与 token 数的关系曲线。
4. 按难度等级分层分析。
5. 多随机种子与置信区间，并在独立的验证集上（而非 MMMU）选择超参数。

## 核实过的外部事实

- VisuLogic：1,000 道四选一单选题，实测随机基线 24.9%，人类 51.4%；Qwen2.5-VL-7B-Instruct 得分 26.0（[VisuLogic 论文](https://arxiv.org/abs/2504.15279)）。
- Qwen2.5-VL-7B-Instruct 官方分数：MMMU val 58.6，MathVision 25.07（[模型卡](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct)）。
